3. Theory Questions & Answers

3.1 What is JWT? Explain its structure and purpose.

A JSON Web Token (JWT) is an open industry standard (RFC 7519) for representing claims securely between two parties. It is compact, URL-safe, and digitally signed.

A JWT consists of three parts separated by dots (.):

  • Header: Specifies token type (JWT) and signing algorithm (e.g. HS256).
  • Payload: Encodes claims including entity id, user role, issued-at time (iat), and expiration time (exp).
  • Signature: Generated using HMAC-SHA256 with the server-side secret key to prevent tampering.

Purpose: Provides stateless authentication so servers do not need to persist session state in database memory.

3.2 Differentiate between Authentication and Authorization

Aspect Authentication (AuthN) Authorization (AuthZ)
Primary Question Who are you? (Identity) What permissions do you have? (Access rights)
Process Validates credentials (email & password) Evaluates assigned role and permission policies
Execution Order Always executed first Executed after authentication is verified
Failure HTTP Code 401 Unauthorized 403 Forbidden

3.3 Why are passwords hashed? What is the purpose of bcrypt?

Passwords are hashed because storing plain text creates catastrophic vulnerabilities if the database is leaked. Hashing is a one-way irreversible transformation.

bcrypt is a cryptographic password hashing function with two key protections:

  1. Salting: Injects a random string before hashing, thwarting dictionary and rainbow-table attacks.
  2. Adaptive Work Factor: An adjustable cost factor (rounds) increases the computation time required to compute hashes, resisting GPU-based brute force attacks.

3.4 Explain the purpose of JWT signing and verification

Signing: When a user logs in, the backend signs the header and payload with a private secret key (JWT_SECRET). No third party can forge this signature without the secret.

Verification: On every request, the backend extracts the token, recalculates the signature using its secret, and compares it with the token's signature. If any payload data (e.g. changing role to admin) was modified, verification fails immediately.

3.5 What is middleware in Express.js? Explain its role in JWT authentication

In Express.js, middleware functions have access to the request object (req), response object (res), and the next() callback function.

In JWT authentication, the protect middleware intercepts requests to protected routes, parses req.headers.authorization, verifies the JWT token with jwt.verify, queries the database for user data, attaches the user to req.user, and calls next() to proceed. If verification fails, it sends a 401 Unauthorized response.

3.6 What is the purpose of Bearer Token in the Authorization header?

The Bearer token scheme conforms to RFC 6750. Sending the token in Authorization: Bearer <token> adheres to REST best practices, decouples credentials from request bodies or URL parameters, and simplifies cross-origin resource sharing (CORS).

3.7 Differentiate between HTTP status codes 401 and 403

  • 401 Unauthorized: The user has not provided authentication credentials, or the credentials/token supplied are invalid or expired.
  • 403 Forbidden: The server knows the user's identity, but the user does not possess the permissions/role necessary to access the requested resource.

3.8 What is Role-Based Access Control (RBAC)?

RBAC is an access management approach where permissions are granted to roles rather than individuals. Users are assigned roles (such as admin or user), and endpoints enforce policies based on the authenticated user's role.
